## Summary

16 requirement entries plus a baseline: REQ-00 (baseline), REQ-01 through REQ-16 in the ADDED/MODIFIED sections (REQ-11 is unused: that analysis item is deferred as DEF-A), and REQ-02R in REMOVED; the multi-projector item is deferred as DEF-B. Every recommendation in `GEV-Redis-Analysis.md` §1–§11e maps to exactly one REQ (mapping table in `README.md`). Files group REQs by pipeline stage: write path (`01-`), read path (`02-`), transport and lifecycle (`03-`), Redis showcase surface (`04-`); shared sections (SUPERSEDED, DEFERRED, DAG, interactions, assumptions, decisions, tests, security, rollback, validation, handoff, history) live in `05-`. Execution order is the topological sort of the `Depends on:` fields (`05-shared-sections.md` → Dependency DAG); document order differs from execution order and is stated there.

Terms used with repo meaning: **live layers** = the three layers whose entities receive a new position every refresh: `flights` (`kind: states`), `military` (`kind: ac`), `ais-live-vessels` (`kind: rows`) — the layers whose modules poll on `updateInterval` (`src/data/flights.js:3893` = 30000 ms, `src/data/aisLiveVessels.js:61` = 60000 ms). **Cold doc** = the existing `gev:<layer>:entity:<family>:<id>` RedisJSON document (`server/redis/README.md` key table). **Hot hash** = the new `gev:<layer>:pos:<id>` Hash introduced by REQ-03. **posidx** = the new `gev:<layer>:posidx` Hash index introduced by REQ-03. **Projection cycle** = one `commit` event processed by `commitSnapshot` (`server/redis/pipeline.js:225-262`): `begin`, N `publish` batches of `batchSize` = 25 (`pipeline.js:44`), M `cleanup` batches, `finish`.
